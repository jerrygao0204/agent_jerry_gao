Modular Architecture Self-Healing Pipeline LLM Quality Audit Zero Infrastructure Touch

核心概括 (Architecture Overview)

Memory Growth Pipeline 是一個專為大語言模型 Agent 設計的高可靠性記憶演進系統。系統採用三階段（Phase）模組化管線架構，結合獨立的 LLMGuard 自我修復防護網，確保長時間跨度的對話碎片能精準抽取並映射為動態演進的三層語境結構 (Profile, Memory, State)。

Phase 1: 1_extractor.py

事實碎片抽取 (Fact Extraction)
採用語義感知重疊滑動窗口 (Semantic Overlap Window)，全量/增量解析對話歷史並追蹤 Message Hash，高召回率提取事實碎片 (Raw Facts)。

Phase 2: 2_layer_mapper.py

規範化與三層映射 (Layer Mapping)
執行 Pass 1 事實清洗與 Pass 2 結構化映射，產出包含 Profile (靜態畫像)、Memory (成長鏈/態度圖譜) 與 State (當前焦點) 的 JSON 記憶體。

Phase 3: 3_context_builder.py

系統語境渲染 (Context Builder)
讀取三層語境數據結構，進行模組化 Prompt 模板渲染，導出可以直接注入系統 Prompt 的純文字 Context。

高可靠性防護網 (LLMGuard Mechanism)

為了確保大模型生成的 JSON 數據 100% 滿足強類型與語法合規要求，系統導入了獨立適配器 5_llm_guard.py，其運作邏輯如下：

🛡️ 5 輪 Self-Healing 重試與雙級評估流程

1. 語法攔截：自動捕捉 JSONDecodeError，將具體報錯行號與列號構造為修復 Prompt 反饋給 LLM。
2. LLM Auditor 二次審查：由 LLM 擔任品質審查專家，針對 schema_desc 規範進行 1-10 分的業務邏輯打分。
3. 最佳版本選取 (Fallback)：若 5 輪均未獲 10/10 滿分，自動比較歷史嘗試，選出得分最高且語法正確的最佳版本。

常用命令行操作說明 (CLI Usage)

系統透過 app.py 作為統一的流程調度入口，支援靈活的參數傳遞：

操作場景 CLI 命令範例 說明
預設增量運行 python app.py --user admin 只處理尚未記錄 Hash 的新對話碎片
全量重新抽取 python app.py --user admin --full-run 清空歷史 Hash 狀態，重新對全量對話執行解析與映射
指定模型與窗口調優 python app.py --user gao --model qwen3-32b --window-size 8 --overlap-size 2 調整滑動窗口大小與重疊邊界，配合指定 LLM 模型
開啟 Debug 日誌 python app.py --user admin --debug 輸出詳細的 LLM 調用日誌與中間驗證過程

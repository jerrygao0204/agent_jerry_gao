GitHub 使用与排错指南

1. 生成 Personal Access Token (PAT)

  • 进入 GitHub 设置 → Developer settings → Personal access tokens
  • 选择 Generate new token (classic)
  • 填写 Token 名称（例如 RAG-private-token）
  • 设置有效期（建议 90 天）
  • 在 Select scopes 中只勾选 repo 权限
  • 点击 Generate token 并复制生成的 Token

2. 在容器中配置 Token 与凭证存储

git config --global credential.helper store
echo "https://jerrygao0204:ghp_xxxxxxxxxxxxxxxxxxxxx@github.com" > ~/.git-credentials

确认配置是否生效：

cat ~/.git-credentials
git config --global credential.helper

3. 标准提交代码流程（含缓存规避）

  1. 进入仓库目录：cd /workspace/hf-conda/RAG/agent_jerry_gao
  2. 检查当前工作区变动： 
    git status
  3. 添加修改的文件（使用 git add -A 或指定檔案）： 
    git add -A
  4. 提交修改并编写清晰的日志： 
    git commit -m "refactor: 描述你的修改内容"
  5. 推送到远程仓库： 
    git push origin main

4. 进阶故障排查与最佳实践

  • 如何彻底清理 Python 编译缓存（*.pyc / __pycache__）： 若发现不小心将 .pyc 二进制缓存提交到了 Git 仓库，可配置 .gitignore 并执行以下命令将其从版本追踪中彻底剥离： 
    git rm -r --cached "**/__pycache__"
git rm -r --cached "**/*.pyc"
git add -A
git commit -m "chore: 清理歷史緩存並加入 gitignore"
  • 理解 Git 档案数与傳輸物件數（Objects）的差異： 执行提交时输出的物件数（如 39 个 objects）通常与实际变动檔案数（如 42 个）不完全一致，这是由于 Git 底层的 Tree、Blob 物件拆解与 Delta 压缩机制导致的，属于正常现象。可使用 git show --stat HEAD 核对变动明细。

5. 注意事项与危险操作红线

  • 不要在 ~/.git-credentials 文件里写尖括号 <>
  • Token 只显示一次，记得妥善保存
  • 只勾选 repo 权限即可，避免过多权限带来安全风险
  • 严禁将 *.pyc 字节码及 __pycache__ 目录提交至远程仓库，务必在仓库根目录维护好 .gitignore 文件
  • 严禁盲目使用具破坏性的 Git 命令：切勿随意执行 git reset --hard 或未经确认的 git checkout .，这会导致本地已修改、尚未提交的高价值代码或重构逻辑被直接清空并永久删除！如需撤销应优先选择温和的软回退（如 git reset --soft）。
